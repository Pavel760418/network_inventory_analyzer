# Методология

## Недостача и излишек

Берутся из выгрузки правилами v4. Модуль не пересчитывает первичную разницу по своей формуле, если колонки суммы уже заполнены.

Чистая недостача операционного контура = недостача строк с `include_in_store_rating=1` минус однородное перекрытие v4 минус автоматически подтверждённые пары справочника. Результат не опускается ниже нуля.

## Пересорт по справочнику

Совпадение только по точному нормализованному имени или id из `config/related_product_pairs.csv`.
Общие слова сами по себе пару не создают.

Статусы:

- «автоматически подтверждено» — тип прямой замены и заполнено `approved_by`. Такая пара уменьшает недостачу в пределах остатка количества.
- «требует ручной проверки» — `requires_manual_review` или нет подтверждающего. Недостача не уменьшается.
- «отклонено» — `active=0` или самопара.

Один излишек не закрывает недостачи сверх своего количества. Одна недостача не закрывается больше чем на 100% количества.

Пример, который требует подтверждения: «Семга стейк» и «Форель стейк». В поставке это кандидат, не утверждённая замена.

## Резерв категории

Допустимое перекрытие = min(недостача категории, излишки категории).
Неперекрытая недостача = max(недостача − факт перекрытия, 0).
Резерв = max(допустимое перекрытие − факт перекрытия, 0).

Единица — рубли за выбранный период выгрузки.
Резерв не вычитается из чистой недостачи и не является экономией.
В факт входят только перекрытие v4 и подтверждённые пары.
Кандидаты и межгрупповые неподтверждённые связи в резерв не входят.
Резерв в рейтинг входит с весом 0.

## Рейтинг магазина

Считается функцией v4 `calc_store_metrics` только по строкам `include_in_store_rating=1`.

Балл = перцентиль shrinkage × 0.35 + перцентиль восстановления × 0.25 + перцентиль чистых недостач × 0.25 + перцентиль числа SKU × 0.15.
Меньший shrinkage и меньшие чистые недостачи дают более высокий компонент.
Более высокий итог — лучше. Место 1 — лучший балл. Равенство балла разрешается по имени магазина.
Магазин без строк контура в рейтинг не попадает.

Излишки, аномалии цен и резерв показаны в детализации с весом 0: в формуле v4 отдельных весов для них нет, новые коэффициенты не назначались.
Хозтовары, тара, упаковка и расходники на балл не влияют. Их деньги остаются в общем итоге.

## Хозтовары

Scope `household_supply`, `packaging`, `container`, `consumable`, `equipment`, `other_non_core` исключаются из рейтинга, топа производственного риска и пересорта ингредиентов.
Общая сумма недостач и излишков их по-прежнему содержит.
Нет классификации — статус «Не классифицировано», строка не исключается.

## Говядина

В суммы блока входят только строки `config/beef_scope.csv` с `active=1`.
`active=0` — на проверке.
Имя содержит «говяд», а строки справочника нет — «предварительно классифицировано», в подтверждённые суммы не входит.

## Оприходование

- A. Есть точная связь с недостачей того же имени в том же магазине.
- B. Есть кандидат справочника. Ущерб не уменьшается.
- C. Связи нет. Текст причины всегда начинается с «Гипотеза причины / требуется проверка».

## Аномалии цен

Это пары точных наименований между магазинами из модуля v4. Отдельная денежная сумма эффекта отклонения ценой v4 не задана, поэтому модуль её не выдумывает.

## Полнота

Детальные листы v2 пишут все строки расчётного набора. Top-10 есть только в резюме, дашборде и на главной странице.
Лист «Полнота_выгрузки_и_контроль» ставит статус OK, когда число строк отчёта равно числу строк расчёта.
