# Масштаб сопоставления пар

Алгоритм v4 в `src/overlap.py` по-прежнему ограничивает декартово сопоставление внутри категории: если произведение сторон больше 2 500 000, с каждой стороны берётся не больше 1 200 крупнейших строк. Этот порог не увеличен, потому что его снятие меняет результат большого расчёта.

Поиск кандидатов собственного производства до этого шага идёт иначе:

- позиции индексируются по семейству из `config/product_family_rules.csv`;
- сравниваются только позиции одного семейства или одного артикула;
- несовместимые единицы отсекаются до финансового расчёта;
- число сравнений и размер семейства ограничены `MAX_CANDIDATE_COMPARISONS` и `MAX_ITEMS_PER_SIDE`.

Режимы в интерфейсе и `MATCHING_MODE`:

| Режим | Смысл |
|-------|--------|
| safe_default | Базовые лимиты 50 000 сравнений и 400 позиций в семействе |
| extended | Порог не ниже 200 000 сравнений и 2 000 позиций |
| full_manual_review | Порог не ниже 1 000 000 сравнений и 5 000 позиций. Кандидаты всё равно не получают approved |

Если лимит сработал, отчёт пишет: «Полный список по расчётному пулу; поиск потенциальных связей ограничен параметром …». Формулировка «100% полный список пар» в этом случае не используется.

Предупреждение для пользователя:

«Полный перебор потенциальных пар ограничен для защиты времени расчёта. При превышении порога используется приоритизированный пул кандидатов. Результат потенциальных пересортов может не включать низкоприоритетные сопоставления. Для полного расчёта необходим расширенный режим.»
